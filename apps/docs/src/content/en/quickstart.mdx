# Quick Start

Use PCU as a deterministic execution layer for pnpm catalog updates. Discovery and execution are
separate, so a developer, CI job, or coding agent can review the exact change before it is written.
{{ className: 'lead' }}

<Note>
  PCU is designed for pnpm workspaces that define dependencies in `catalog` or `catalogs` inside
  `pnpm-workspace.yaml`.
</Note>

## Install

<CodeGroup>

```bash {{ title: 'npm' }}
npm install --global pcu
```

```bash {{ title: 'pnpm' }}
pnpm add --global pcu
```

```bash {{ title: 'No global install' }}
pnpm dlx pcu --help
```

</CodeGroup>

Node.js 20 or newer and pnpm 9 or newer are supported.

## Create a reviewable plan

Run this from the workspace root:

```bash
pcu plan --target minor --out pcu-plan.json
```

The JSON artifact is stable and portable. It contains:

- a versioned schema;
- the exact catalog updates and affected workspace packages;
- normalized filters and update criteria;
- a SHA-256 fingerprint of `pnpm-workspace.yaml`;
- no timestamp, localized prose, or absolute checkout path.

Review `pcu-plan.json` directly or commit it as part of an approval workflow.

## Apply exactly the reviewed plan

```bash
pcu apply pcu-plan.json
```

Before writing, PCU validates the schema and checks the source fingerprint. It refuses a stale plan,
uses atomic workspace persistence, creates a rollback backup by default, and verifies the final
catalog versions. `apply` does not query the registry or call an AI provider.

Applying the same plan again is safe: if every target version is already present, PCU returns success
with `changed: false`.

To regenerate the lockfile in the same step, opt in explicitly:

```bash
pcu apply pcu-plan.json --install
```

## Verify in CI

```bash
pcu verify pcu-plan.json
```

`verify` compares each planned target with the current catalog state and emits JSON. Exit code `0`
means an exact match; exit code `4` means drift.

## Recover

```bash
pcu rollback --from <backupPath> --yes --json
```

Unless `apply` was run with `--no-backup`, its JSON result contains `update.backupPath`. Passing that
exact path to the JSON rollback contract restores the reviewed pre-apply file without prompts and
verifies its catalog structure. Interactive `pcu rollback` remains available for humans.

## Exit codes

| Code | Meaning |
| ---: | --- |
| `0` | Success, including an already-applied plan |
| `2` | Invalid input or execution/install failure |
| `3` | The plan is stale |
| `4` | Verification failed |
| `5` | The plan contains unresolved conflicts |

## Optional advisory tools

Use the interactive commands when you are exploring rather than automating:

```bash
pcu check
pcu update --interactive
pcu analyze react 19.0.0
pcu security
```

AI analysis is opt-in with `pcu update --ai`. It can explain a proposed change, but it is never in
the `plan → apply → verify` execution path.
